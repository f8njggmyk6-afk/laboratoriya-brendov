# Панель заказов — российский VPS

Дата: 31 октября 2026 года.

Эта инструкция относится только к изолированной ветке `russia-vps-local-backend`. Это отдельная российская версия проекта: текущий сайт Vercel и его база данных не изменяются до согласованного переключения домена.

## Настройка перед запуском

Сборка для VPS:

```sh
npx vite build --config vite.russia.config.ts
```

Запускать нужно Node-сервер из `.output-russia/server/index.mjs`; одних статических файлов недостаточно для API.

Создайте на VPS отдельный env-файл `/etc/laboratoriya-brendov.env`, владелец `root:root`, права `0600`. Не коммитьте его и не отправляйте секреты в чат.

Обязательные переменные:

- `LB_SQLITE_PATH=/var/lib/laboratoriya-brendov/orders.sqlite`
- `LB_ADMIN_EMAIL` — единственная почта владельца панели; на неё приходят коды входа.
- `RESEND_API_KEY` и `RESEND_FROM_EMAIL` — отправитель одноразовых кодов владельцу. Секрет нужен только для входа; данные клиентских заявок через Resend не отправляются.
- `LB_ADMIN_ENABLED=false` до настройки почты, TLS и резервных копий. Менять на `true` только после этих проверок.

Постоянного пароля администратора в российской версии нет.

## Вход и защита

Владелец открывает `/admin`, запрашивает шестизначный код на `LB_ADMIN_EMAIL` и вводит код из письма. Код действует 10 минут; отправка и попытки проверки ограничены по частоте. Сессионный токен хранится в базе только в виде хеша; cookie — HttpOnly, Secure и SameSite=Strict, срок сессии — 8 часов.

Запросы записи проверяют источник, вход и состояние заказа на сервере. Сервис работает от непривилегированного пользователя `lbapp`; право записи ему нужно только для каталога базы данных.

## Заказы и уведомления

Заявки и история изменений записываются в локальную SQLite-базу на VPS. Изменения заказа проверяются сервером; конфликт правок из другой вкладки отклоняется по версии записи. Удаление заказа обратимое.

Российская версия не пересылает данные клиента через Resend. После заявки владелец должен проверить панель заказов; перед запуском необходимо отдельно выбрать и настроить подходящий канал уведомлений. Передача в MAX остаётся действием самого пользователя.

Страница отслеживания получает только публичную проекцию заказа по tracking-коду.

## Резервные копии и запуск

Хранилище и резервные копии должны быть доступны только системному пользователю приложения и администраторам VPS. Настройте регулярные защищённые копии и проверьте восстановление до подключения реальных клиентов.

Примеры systemd и Nginx находятся в `deployment/russia/`. Замените домен и пути сертификата в Nginx-примере; публиковать приложение можно только за TLS reverse proxy. Прокси должен перезаписывать `X-Forwarded-For` адресом клиента.

Перед production проверьте на подставных данных создание заявки, MAX-переход, вход владельца по коду, правки, историю, обратимое удаление и публичное отслеживание. Отдельно проверьте восстановление из резервной копии.

Существующих заказов для переноса нет, миграция не требуется. До подключения реальных клиентов валидируйте сайт на российских мобильных и фиксированных сетях. Проверьте уведомления, сроки хранения, текст о приватности и требования к уведомлению оператора по фактическому процессу.

Текущий Vercel deployment и DNS держите доступными для отката до проверки нового сайта. Переключайте DNS только после проверок и решения владельца.
