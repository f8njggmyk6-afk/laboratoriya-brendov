# Панель заказов — подключение и эксплуатация

Дата: 24 октября 2026 года.

## Готово в коде

- Отдельный закрытый интерфейс `/admin`, без ссылок в клиентском меню и sitemap.
- Код входа отправляется только на `LB_ADMIN_EMAIL`; регистрация клиентов не предусмотрена.
- Проверка пользователя через Supabase Auth на каждом запросе; учётная запись из frontend или user_metadata не даёт прав.
- HttpOnly, Secure, SameSite=Strict cookies; токены не передаются в JSON и не кладутся в localStorage.
- Список последних 300 заказов, поиск, фильтр статуса, даты по Москве.
- Исходные услуги и суммы из прайса сохраняются отдельно от редактируемой согласованной суммы, срока и состава.
- Редактирование имени, email, суммы, даты сдачи, состава, заметок, статуса, подтверждения условий, оплаты и передачи файлов.
- История изменений; защита от перезаписи правок другой вкладкой через version.
- «В работе» требует согласованных условий, суммы, состава и срока; завершение требует оплаты и передачи файлов.
- Новые заявки сохраняются до почтового уведомления. При сбое уведомления заказ остаётся в базе, пометка видна владельцу.
- Idempotency-Key защищает от повторного создания заказа при повторной отправке того же запроса.
- Лимиты попыток входа и входящих заявок хранятся в базе и действуют между serverless-инстансами.
- Все таблицы закрыты RLS и REVOKE от anon/authenticated; прямой доступ из браузера запрещён.
- SQL-функции SECURITY INVOKER, доступны только service_role. Серверный ключ никогда не попадает в клиентский JS.

## Состояние подключения

Отдельный проект `laboratoriya-brendov-orders` (`pvgqsngydvxvluteyfmn`), регион eu-west-3. Стоимость создания по проверке провайдера — $0/месяц на 24 октября 2026 года; последующие тарифы и лимиты могут измениться. Проект Nirvana не изменялся.

Применена миграция `brand_lab_orders_admin`. Живая проверка SQL в транзакции с ROLLBACK подтвердила обновление, историю, конфликт версий, обязательное согласование условий, контроль завершения/суммы и лимиты. Права anon/authenticated на таблицы и RPC закрыты. Security advisor сообщает только ожидаемое INFO о RLS без политик: доступ из браузера намеренно запрещён.

Сервер сайта обращается к `lb-admin-gateway` через отдельный случайный токен. Его SHA-256 находится в конфигурации функции, сам токен — только в защищённой переменной Vercel. Корневой service_role ключ остаётся внутри Supabase и не копируется на сайт. Функция проверяет токен самостоятельно, разрешает только таблицы/RPC ЛБ и необходимые auth-методы; выдача кода ограничена почтой владельца. verify_jwt=false нужен для этой собственной аутентификации, а не для анонимного доступа.

## Переменные production Vercel

- `LB_SUPABASE_URL`: URL отдельного проекта.
- `LB_ADMIN_GATEWAY_TOKEN`: случайный секрет, только server-side encrypted/sensitive env.
- `LB_ADMIN_EMAIL`: laboratoriabrendov@gmail.com.
- `LB_ADMIN_ENABLED=true`: включается после проверки схемы и gateway.
- Существующие `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `NOTIFY_TO_EMAIL` сохраняются.

При ротации gateway-токена заменить его хеш в config.ts, выпустить Edge Function и обновить защищённую переменную Vercel с последующим deployment. Не помещать сам токен в git, браузер или журналы.

## Первый вход и установка

Открыть `https://laboratoriyabrendov.com/admin`, указать почту владельца и самостоятельно ввести полученный код. Агент не читает и не вводит код за владельца. Живой первый вход и доставка письма владельцу проверяются самим владельцем; автоматические проверки не отправляют реальные письма.

Добавление `/admin` на главный экран использует отдельный manifest (`id`, `start_url` и `scope` — `/admin`), имя «ЛБ Заказы». Добавление `/` использует обычный manifest. Можно сохранить только панель или два независимых значка.

## Контроль после выпуска

Проверить рабочий deployment, активную форму входа, запрет доступа к заказам без сессии, отклонение посторонней почты и manifest. Для проверки настоящего входа код запрашивает сам Давид. Мок-тесты не заменяют эту проверку.

## Проверки без подключения

`npm run build`
`node scripts/check-admin.mjs`
`node scripts/check-admin-gateway.mjs`
`node scripts/check-pricing.mjs`

Проверки используют подставные почтовый транспорт и базу. Это подтверждает маршрутизацию/проверки в коде, но НЕ заменяет проверку живой Supabase базы после подключения.

## Не входит в эту версию

Чтение переписки, автоматические выводы Нирваны о сумме/сроке, интеграции с мессенджерами, клиентские личные кабинеты и импорт старых писем. До подключения мессенджеров почтовое уведомление остаётся действующим.
