# Панель заказов — российский VPS

Дата: 30 октября 2026 года.

Эта инструкция относится только к изолированной ветке `russia-vps-local-backend`. Это preview миграции: production DNS и текущая база Vercel/Supabase не менялись. Инструкции Vercel/Supabase ниже по старым документам к этой ветке не применяются.

## Настройка перед запуском

Сборка для VPS:

```sh
npx vite build --config vite.russia.config.ts
```

Запускать нужно Node-сервер из `.output-russia/server/index.mjs`: одних статических файлов недостаточно для API.

Создайте на VPS отдельный env-файл `/etc/laboratoriya-brendov.env`, владелец `root:root`, права `0600`. Не коммитьте его и не отправляйте пароль в чат.

Обязательные переменные:

- `LB_SQLITE_PATH=/var/lib/laboratoriya-brendov/orders.sqlite`
- `LB_ADMIN_EMAIL` — единственная почта владельца панели.
- `LB_ADMIN_PASSWORD` — уникальный секрет не короче 32 символов.
- `LB_ADMIN_ENABLED=true` — включать только после настройки пароля и HTTPS.

До этого оставьте `LB_ADMIN_ENABLED=false`. Сервис запускается от непривилегированного пользователя `lbapp`; доступ на запись ему нужен только в каталог базы данных.

## Вход и защита

Владелец входит на `/admin` по почте и паролю. Регистрации, входа через Supabase и отправки одноразовых кодов в этой версии нет. Сессионный токен хранится в БД только в виде хеша; cookie — HttpOnly, Secure и SameSite=Strict, срок сессии — 8 часов. Запросы записи проверяют источник, вход и новые заявки ограничиваются по частоте.

## Заказы и уведомления

Заявки и история изменений записываются в локальную SQLite-базу на VPS. Изменения заказа проверяются сервером; конфликт правок из другой вкладки отклоняется по версии записи. Удаление заказа обратимое.

Российская версия не пересылает данные клиента через Resend. После заявки владелец должен проверить панель заказов; перед запуском необходимо отдельно выбрать и настроить подходящий канал уведомлений. Передача в MAX остаётся действием самого пользователя.

Страница отслеживания получает только публичную проекцию заказа по tracking-коду. Существующие производственные номера и историю в эту базу пока не переносили.

## Резервные копии и запуск

Хранилище и резервные копии должны быть доступны только системному пользователю приложения и администраторам VPS. Настройте регулярные защищённые копии и проверьте восстановление до подключения реальных клиентов.

Примеры systemd и Nginx находятся в `deployment/russia/`. Замените домен и пути сертификата в Nginx-примере; публиковать приложение можно только за TLS reverse proxy. Прокси должен перезаписывать `X-Forwarded-For` адресом клиента.

Перед production проверьте подставными данными: создание заявки, MAX-переход, вход владельца, правки, история, обратимое удаление и публичное отслеживание. Отдельно согласуйте перенос текущих заказов и подготовьте откат на Vercel. DNS переключать только после этих проверок и отдельного решения владельца.
